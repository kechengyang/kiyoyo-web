01 / PRODUCT

产品不是“奶茶 + 商城”，而是一条品牌飞轮

把“附近、即时、高频”的饮品，与“稀缺、收藏、社交传播”的 IP 商品放在同一会员体系里。每次购买都应推动下一次互动，而不是在支付成功页结束。

PRODUCT THESIS
高频饮品负责建立习惯，限量 IP 商品负责制造期待。

积分、徽章、优惠券和收藏夹把两种消费节奏连接起来。

KIYOYO GROWTH LOOP
喝到快捷点单、自取/外送
积累积分、等级、连续消费
收藏商品、系列、限定权益
分享新品、盲盒、社交传播
北极星：建议以“月度活跃购买会员数”为总指标，同时观察饮品复购与 IP 商品交叉购买。
02 / EXPERIENCE

五个一级入口，各自只有一个核心任务

沿用概念图的底部导航。Home 负责“现在买什么”，Shop 负责“深入逛什么”，Collection 负责“以后想买什么”，Cart 负责“怎么一起结算”，Account 负责“我获得了什么”。

03 / JOURNEYS

两类商品，两条履约链

前台可以保持统一，但后台必须明确区分“现制饮品”和“普通商品”。它们的时效、库存、取消条件、核销方式完全不同。

01选门店/地址先确定服务范围、预计时间和可售菜单。
02定制饮品规格、甜度、冰量、加料；实时显示差价。
03选择履约店内自取或外送；展示时段与费用。
04虚拟支付Mock 成功后生成订单号并进入制作；失败/超时可重试。
05制作/通知已接单 → 制作中 → 可取/配送中。
06核销完成自取出示一次性二维码，员工扫码后完成。
关键规则：二维码不是订单号图片，而是一次性核销凭证；只允许正确门店、正确状态的订单核销，重复扫描必须提示“已核销”。
01发现商品品类、系列、Drop、搜索与收藏。
02选择规格款式、尺码、限购规则和库存提示。
03确认信息收货地址、联系方式与商品明细。
04虚拟支付通过 Mock 支付确认，生成订单号并保存完整快照。
05人工处理后台查看、备注、更新订单状态。
06未来扩展库存预占、发货、物流追踪与售后。
MVP 边界：先保证订单可查、信息完整、金额一致、后台可处理；自动物流和复杂售后放到下一阶段。
04 / ORDER MODEL

用户一次付款，系统拆成多个“履约组”

这项决策能同时保留“统一购物车”的体验和“不同业务独立履约”的可操作性，也是未来多门店、邮寄、预售扩展的基础。

价格快照

下单时保存商品名、规格、单价、折扣与税费快照，后续改价不能改变历史订单。

库存边界

饮品按门店可售状态；商品按 SKU 库存。混合购物车不能让两种库存逻辑互相污染。

取消边界

饮品开始制作后原则上不可自助取消；商品发货前可按运营规则申请取消。

05 / STORES

内罗毕六家门店：先选最近，再让用户确认

用户授权定位后，系统对 Nairobi 六个已知门店坐标计算直线距离并默认选中最近门店。地图只在用户打开时加载；选中门店后，服务端再次验证营业状态、菜单和自取/配送能力。

06 / MEMBERSHIP

会员系统先做“可理解”，再做“有趣”

MVP 只需要一套清晰的积分账本与优惠券规则。等级、徽章、连续签到、收藏册等游戏化能力，应建立在数据可靠之后。

POINTS

积分是账本，不只是余额

每笔获得、使用、过期、撤销都留记录；退款时可追溯地回滚。

COUPONS

优惠券明确可用范围

饮品/商品、门槛、门店、时段、是否可叠加，结账前解释不可用原因。

REWARDS

奖励连接两类消费

例如“买 5 杯解锁限定商品优先购”，建立饮品到 IP 的交叉转化。

HISTORY

历史订单支持一键再来

饮品按原配方复购；缺货加料或门店不可售时提示用户调整。

07 / ADMIN

后台不是报表集合，而是门店工作台

MVP 后台按真实工作顺序组织：先处理眼前订单，再查问题订单，最后看用户与运营数据。移动端也要能快速核销。

饮品核销 门店端

扫码 / 手输取餐码

相机不可用时必须有备用入口。

订单校验与确认

门店、状态、明细、核销时间一屏确认。

异常处理

已核销、错误门店、退款中均给出明确提示。

订单管理 运营端

实时订单队列

按门店、类型、状态、时段筛选。

详情与操作记录

支付、状态变化、员工操作完整留痕。

商品订单处理

MVP 支持备注、确认、取消、导出。

用户管理 客服端

会员 360° 视图

订单、积分、券、地址与服务记录。

受控的积分调整

必须填原因并记录操作人，禁止直接改余额。

角色与权限

店员、店长、客服、运营、超级管理员分权。

09 / ROADMAP

分阶段交付，先验证真实门店闭环

以下为经营层规划带，不是固定工期承诺。实际周期取决于支付、配送、税务、门店设备与 App 审核要求。

PHASE 1 · VALIDATE

Web / PWA + 后台

六店配置到位，先选一店灰度，再逐店开放。

  • 定位与最近门店默认选择
  • Mock 支付、饮品点单与二维码核销
  • 商品下单与人工处理
  • 基础会员、订单/用户/核销后台
PHASE 2 · RETAIN

iOS / Android

在业务规则稳定后放大复购。

  • 原生推送、深链接
  • 到货与可取提醒
  • 更顺滑的复购和会员体验
  • 应用商店发布与增长归因
PHASE 3 · SCALE

IP 商业化

围绕稀缺性与收藏关系扩展。

  • Drop、预售、限购、盲盒规则
  • 物流、售后、库存预占
  • 收藏图鉴与会员等级
  • 多门店与运营自动化
